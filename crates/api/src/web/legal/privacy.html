Privacy Policy

This policy covers the hosted jModGuard Discord bot and its dashboard. We use the data below to moderate servers, keep moderation records, and show server settings and reports to people with access.

What we receive from Discord

The bot requests the Guilds, Server Members, Guild Messages, Message Content, Guild Moderation, and Guild Voice States gateway intents. Server Members lets us maintain the member directory and report membership changes. Message Content lets us check messages for spam and other rule violations and provide the message logs a server enables. We do not request the Presence intent.

If you sign in to the dashboard, Discord provides your account identity and server list. We check server permissions and, where configured, your roles in that server. A session cookie keeps you signed in.

What we keep

  • Dashboard sessions. While you are signed in, the API keeps your Discord user ID, OAuth access token, and refresh token (when Discord issues one) in a server-side session in memory keyed by your session cookie. We use the access token to look up your servers and check your permissions, and the refresh token to renew access if needed. Signing out clears the session. After 7 days of inactivity the session expires and can no longer be used. Expired records can remain in memory until the API restarts. Restarting the API clears all sessions.
  • Member directory. We keep Discord user IDs, the latest observed usernames, display names and server nicknames, known join and leave dates, membership stays, and links to selected moderation cases. We keep current members in the directory while they are in the server. If you leave without confirmed ban history, your entry becomes eligible for cleanup after five minutes. Verification or an outage can delay cleanup. Confirmed ban history and known membership context can stay through an unban, rejoin, and later departure.
  • Message snapshots. If a server has a destination for message-edit, message-delete, bulk-delete, or automod-delete logs, the bot can keep the latest observed text, message and author details, and attachment details such as filenames, sizes and Discord links for eligible human messages. Snapshot data expires within 24 hours of the original post. Edits never extend that window, and expired rows are removed by a cleanup job. A short-lived copy in memory follows the same expiry. Snapshots contain no attachment file bytes. There is no general message archive.
  • Exact-image spam. The bot reads image files to calculate hashes for exact matches. It keeps hashes as image evidence, without storing the image files. A related moderation case can also keep text excerpts from the messages.
  • Moderation records. We keep selected moderation events, warnings, bans, cases, and case history for server moderation. Cases can include Discord IDs, the action and reason, case notes, and evidence. Cases and their history have no automatic age limit and are kept until removed by someone with permission or erased with the server.
  • Analytics. Membership analytics keep daily join and leave totals per server, without user IDs. When a server’s counters are updated, totals more than 92 days old are pruned. The dashboard also summarizes existing moderation records, including action counts by moderator.
  • Server settings. We keep server settings and the latest role and channel names and IDs, along with display details such as order and role colors, for the rule editor.

Who can see data and what servers control

Access to the member directory, moderation cases, and settings in the dashboard requires Discord sign-in and permission for that server. Reports sent to a configured Discord log channel are visible to people with access to that channel. Server administrators can choose log destinations and set ignored users and source channels for each event. Those lists filter delivery to Discord. Snapshot capture, rule enforcement, and moderation records are handled separately.

The Discord platform provides the server, bot, and sign-in services and receives actions and reports sent there. The operator’s subprocessors may provide hosting, storage, content delivery, and database services. Apart from the server access described above, we share this data only with the providers we use to operate jModGuard. We do not sell this data or use it to train AI or machine-learning models.

When the bot is removed

After jModGuard confirms it has been removed from a server, an erasure job removes the departed installation’s live cases, snapshots, member directory, configuration, and stored evidence. Reports already posted to Discord follow Discord’s retention and the server’s own handling. Hosting-provider backup copies may persist for the provider’s retention period, which we do not control.

Request deletion or ask a privacy question

  1. Follow the operator’s deletion instructions above.
  2. We aim to respond within 30 days. Before we act, we’ll verify that you control the Discord account whose data you want removed.
  3. After verification, we look for the Discord user ID across the servers we host and manually remove matching member-directory entries and saved message snapshots. We keep cases and their history when a server needs them for moderation. We tell you what we removed and what we retained. If you stay in or rejoin a server using jModGuard, new activity or a member sync can create new entries.
Sources for the dashboard session disclosure
  • Session contents, sign-out, inactivity and restart are defined in crates/api/src/web/mod.rs by store_login_session, logout, router and router_with_store.
  • Permission checks and token renewal use the session in crates/api/src/web/mod.rs. The Discord guild and member-role calls are in crates/api/src/web/oauth.rs.
  • The in-memory store, tower-sessions-memory-store, is pinned in Cargo.lock. Its MemoryStore::load stops returning expired records. The API also expires its in-memory authentication state through sweep_auth_sessions in crates/api/src/web/state.rs.

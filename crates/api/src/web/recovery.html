Update bot and API together

Database changes require both services to update. Both releases are downloaded and verified before the API stops. The bot then migrates the databases, and the matching API starts. Expect a brief service interruption and another sign-in.

After migration starts, recovery uses the selected release or a newer compatible pair. An older release cannot safely be restored. Closing this page does not cancel an upgrade.

This page remains available from the API address if application startup fails. Updates stay inside the containers; they cannot replace the base operating system.

Checking a pair selects that channel for both services and turns their automatic installation off. If either image is missing, or the check cannot be stored, neither service's channel or candidate changes.
